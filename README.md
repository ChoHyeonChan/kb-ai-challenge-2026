# 「왜 안 되지?」 — 은행 앱 실행 실패 원인 판정 엔진

> 제8회 KB Future Finance A.I. Challenge 출품작
> **흩어진 약관·이용조건을 기계가 판정할 수 있는 규칙으로 바꿔, 지금 무엇에 막혔는지 근거와 함께 지목합니다.**

---

## 문제

은행 앱은 **"왜 안 되는지"** 를 말하지 않습니다.

```
앱:    "신분증이 인식되지 않습니다. 다시 촬영해 주세요."
사용자: 재촬영 반복 → 포기
실제:  비대면 계좌개설 안심차단이 켜져 있음
       → 아무리 다시 찍어도 안 됨. 영업점에 가야 함
       → 그 사실은 연 2회만 고지됨
```

해외결제도 같습니다. **조건은 7개인데 설정 화면에는 2개만 보입니다.**
검색하면 FAQ가 뜨지만 *"확인하세요"* 라고 말할 뿐, **확인해주지는 않습니다.**

> ### "확인하세요"와 "확인해드렸습니다"의 차이

---

## 해결

```
KB 공개문서 (약관·이용조건·FAQ)
      │
      ├─ [LLM] 조건 추출 ─────────→  조건 트리  ← ★ 재사용 가능한 자산
      │        directed symbolic       (근거 원문 링크 필수)
      │        prompting
      │
사용자 상태 ─┐
             ├─ [규칙 엔진] 판정 ──→  미충족 항목 + 근거 + 해결 경로
조건 트리 ───┘   결정론적. LLM 개입 없음
```

**판정은 LLM이 하지 않습니다.** 같은 입력에 항상 같은 결과가 나오며, 그 일치율을 측정해 함께 제출합니다.
LLM은 **비정형 문서에서 조건을 뽑아내는 일**과 **사유를 설명하는 일**만 합니다.

→ Retrieval-Augmented **Generation**이 아니라 Retrieval-Augmented **Verification**.

## 빠른 시작

```bash
pip install -r requirements.txt
cp .env.example .env          # API 키 입력
./run.sh                       # 데모 실행 → http://localhost:8000
```

전체 재현 절차는 [docs/REPRODUCE.md](docs/REPRODUCE.md) — **새 폴더에서 처음부터** 돌린 로그를 포함합니다.

## 데모 시나리오

### ① 해외결제 — 흔한 문제
```
"해외 결제가 안 돼요"

판정 — 조건 7개 중  미충족 2 · 확인불가 1
  ✕ 해외거래정지 (온라인)      → KB Pay > 해외이용서비스   [근거 ▾]
  ✕ 해외원화결제 차단          → 같은 화면 내 별도 항목     [근거 ▾]
  ✓ 카드 뒷면 서명 · 1회 가맹점 한도 · T&E 누적 한도
  ~ 결제 시점 유효기한         (원문이 '체류 기간' 기준 — 해석 개입)
  ? 카드–여권 영문명 일치      (여권 정보 미보유)

  ⚠ 두 항목은 각각 해제해야 합니다. 하나만 해제하면 결제되지 않습니다.
```

### ② 비대면 계좌개설 — 극단적 사례
```
앱: "신분증이 인식되지 않습니다."

판정
  ✕ 비대면 계좌개설 안심차단 ON
       · 앱에서 해제 불가 — 영업점 방문 필요
       · 전 금융권 공통 적용 (타행·증권사도 동일)
       [근거] KB 보안센터 안심보안서비스 원문 ▾
  ✓ 신분증 촬영 품질 · 본인명의 휴대폰 인증

  → "다시 촬영해도, 다른 은행에 가도 개설되지 않습니다."
```

## 설계 원칙

| 원칙 | 구현 |
|---|---|
| **근거 없는 판정을 하지 않는다** | 조건 스키마에 `evidence` 필수 → 근거 표시율이 구조적으로 100% |
| **모르는 건 모른다고 한다** | 판정 결과를 `met`/`unmet`/`unknown`/`low_confidence` 4분류. 전부 ✓/✕로 채우지 않음 |
| **해석이 개입하면 표시한다** | 원문을 그대로 옮기지 못한 조건은 `confidence: medium` |
| **앱에서 못 고치는 것을 구분한다** | `remedy.actionable_in_app` — 안심차단이 `false` |
| **같은 입력엔 같은 출력** | 판정 경로에서 LLM 호출 금지. 일치율 측정해 제출 |

## 검증 지표

| 지표 | 방법 | 결과 |
|---|---|---|
| 결정론성 | 동일 입력 N회 반복 일치율 | `eval/results/` |
| 근거 표시율 | 판정 중 evidence 링크 비율 | 구조적 100% |
| 조건 추출 정확도 | 수동 라벨 대비 정밀도·재현율 | `eval/results/` |
| 탐색 시간 대비 | 사람이 직접 확인하는 시간(실측) vs 판정 응답 시간 | `eval/results/` |

## 데이터 출처와 한계

**실제**: 조건 트리는 KB 공개 안내·약관·FAQ에서 자동 추출한 것입니다. 각 조건에 **출처 URL·원문 인용·수집 일자**가 붙어 있습니다.
**가상**: 사용자 상태는 데모용 프로필입니다. 실제 연동에는 내부 API가 필요합니다.

> 이 시스템에서 가짜는 **사용자 상태 하나뿐**입니다. 나머지는 전부 실제 문서에서 나옵니다.

전체 한계와 근거 등급은 [docs/기획안.md](docs/기획안.md) 12장 및 [docs/EVIDENCE.md](docs/EVIDENCE.md) 참조.

### 수집 규율
- robots.txt 확인 후 허용 경로만, 요청 간격 1초 이상
- 공시·안내 페이지만 수집 (로그인 뒤 개인화 페이지 제외)
- 원문 재배포 없이 **인용 스니펫 + 출처 URL**만 표시
- 모든 조건에 수집 일자 기록 (약관은 개정됨)
