# 「다 됐나요?」 — 은행 앱 실행 실패 원인 판정 엔진

> 제8회 KB Future Finance A.I. Challenge 출품작
> **흩어진 약관·이용조건을 기계가 판정할 수 있는 규칙으로 바꿔, 지금 무엇에 막혔는지 근거와 함께 지목합니다.**

---

## 문제

은행 앱은 **"왜 안 되는지"** 를 말하지 않습니다.

```
앱:    "신분증이 인식되지 않습니다. 다시 촬영해 주세요."
사용자: 재촬영 반복 → 포기
실제:  비대면 계좌개설 안심차단이 켜져 있음
       → 아무리 다시 찍어도 안 됨. 영업점에 가야 함
       → 그 사실은 연 2회만 고지됨
```

해외결제도 같습니다. KB Pay 설정 화면에 보이는 항목은 **2개**지만,
KB 공개문서에서 자동으로 뽑아낸 조건은 **11개**입니다. 그중 **8개는 앱에서 해결할 수 없습니다.**
검색하면 FAQ가 뜨지만 *"확인하세요"* 라고 말할 뿐, **확인해주지는 않습니다.**

> ### "확인하세요"와 "확인해드렸습니다"의 차이

---

## 해결

```
KB 공개문서 (약관·이용조건·FAQ)
      │
      ├─ [LLM] 조건 추출 ──→ [규칙] 검증·병합 ──→ [사람] 검수 ──→ 조건 트리
      │   directed symbolic    인용이 원문에         승인/반려만      ★ 재사용 자산
      │   prompting            있는지 확인            (조건을 쓰지     (근거 원문 필수)
      │                        문서 간 중복 제거       않는다)
사용자 상태 ─┐
             ├─ [규칙 엔진] 판정 ──→  미충족 항목 + 근거 + 해결 경로
조건 트리 ───┘   결정론적. LLM 개입 없음
```

**판정은 LLM이 하지 않습니다.** 같은 입력에 항상 같은 결과가 나오며, 그 일치율을 측정해 함께 제출합니다.
LLM은 **비정형 문서에서 조건을 뽑아내는 일**과 **사유를 설명하는 일**만 합니다.

→ Retrieval-Augmented **Generation**이 아니라 Retrieval-Augmented **Verification**.

## 빠른 시작

```bash
pip install -r requirements.txt
cp .env.example .env          # API 키 입력
./run.sh                       # 데모 실행 → http://localhost:8000
```

전체 재현 절차는 [docs/REPRODUCE.md](docs/REPRODUCE.md) — **새 폴더에서 처음부터** 돌린 로그를 포함합니다.

## 데모 시나리오

### ① 해외결제 — 흔한 문제
```
"해외 결제가 안 돼요"

판정 — 조건 11개 중  미충족 3 · 확인불가 1
  ✕ 해외거래정지가 해제되어 있어야 합니다      → 앱에서 가능: KB Pay 에서 해제   [근거 4곳 ▾]
  ✕ 해외원화결제(DCC) 차단이 해제되어 있어야   → 앱에서 가능: 같은 화면 별도 항목 [근거 3곳 ▾]
  ✕ IC칩 비밀번호가 등록되어 있어야 합니다      → 앱에서 불가: 영업점 또는 ATM    [근거 5곳 ▾]
  ✓ 카드 잠김 없음 · 명의도용 차단 해제 · 뒷면 서명 · 1일/1회/T&E 한도 · 유효기한
  ? 카드–여권 영문명 일치                      (여권 정보 미보유)

  ⚠ 앞의 두 개는 같은 화면에 있지만 **각각 따로** 풀어야 합니다.
    하나만 풀면 결제되지 않습니다. 세 번째는 앱에서 아예 풀 수 없습니다.
    앱은 이 중 무엇도 말해주지 않습니다.
```

### ② 비대면 계좌개설 — 극단적 사례
```
앱: "신분증이 인식되지 않습니다."

판정
  ✕ 비대면 계좌개설 안심차단이 해제되어 있어야 합니다
       · 앱에서 해제 불가 — 영업점 방문 필요 (신분증 지참)
       [근거] "새로운 계좌를 만들려면 서비스를 해제해야 하는데요.
               서비스 해제는 반드시 지점을 방문해 직접 신청해야 합니다." ▾

  → "다시 촬영해도, 다른 은행에 가도 개설되지 않습니다."
```

### ③ 하나만 풀면 되나요 — 이 서비스의 답

조건을 나열해 주는 것만으로는 부족합니다. **하나를 풀어도 여전히 막힌다는 사실**을 먼저 말해야 합니다.

```
3개를 모두 해결해야 합니다. 하나만 해결하면 여전히 막힙니다.
그중 1개는 앱에서 할 수 없어, 그것이 전체 소요를 결정합니다 — 먼저 시작하세요.

  해외원화결제(DCC) 차단 해제 만  →  여전히 안 됩니다 · 필수 조건 2개 남음
  IC칩 비밀번호 등록 만           →  여전히 안 됩니다 · 필수 조건 2개 남음
  해외거래정지 해제 만            →  여전히 안 됩니다 · 필수 조건 2개 남음
  앱에서 할 수 있는 것 모두       →  여전히 안 됩니다 · 필수 조건 1개 남음
  3개 모두                        →  됩니다
```

이 계산에도 **LLM은 쓰지 않습니다.** 판정 결과를 집합 연산으로 다시 평가할 뿐이며,
없는 사용자 값을 지어내지 않습니다. 같은 판정이면 언제나 같은 계획이 나옵니다.

> 위 조건의 **문장은 전부 KB 공개문서에서 자동 추출**한 것입니다. 사람이 새로 쓴 문장은 없습니다.
> 사람이 한 일은 셋뿐이고, 전부 [data/review/decisions.yaml](data/review/decisions.yaml) 에 사유와 함께 기록돼 있습니다.
>
> | 사람이 한 일 | 건수 |
> |---|---|
> | 승인 / 반려 판단 | 16건 판단 → 12 승인 · 4 반려 |
> | severity 교정 (blocking ↔ warning) | 3건 |
> | 여러 인용 중 대표 선택 (모델이 뽑은 것 중에서만) | 1건 |
>
> 교정·선택한 조건은 트리에 `review_override` 로 남아, 무엇을 사람이 손댔는지 감춰지지 않습니다.

## 설계 원칙

| 원칙 | 구현 |
|---|---|
| **근거 없는 판정을 하지 않는다** | 조건 스키마에 `evidence` 필수 → 근거 표시율이 구조적으로 100% |
| **모르는 건 모른다고 한다** | 판정 결과를 `met`/`unmet`/`unknown`/`low_confidence` 4분류. 전부 ✓/✕로 채우지 않음 |
| **해석이 개입하면 표시한다** | 원문을 그대로 옮기지 못한 조건은 `confidence: medium` |
| **앱에서 못 고치는 것을 구분한다** | `remedy.actionable_in_app` — 안심차단이 `false` |
| **같은 입력엔 같은 출력** | 판정 경로에서 LLM 호출 금지. 일치율 측정해 제출 |

## 검증 지표

| 지표 | 방법 | 결과 |
|---|---|---|
| 조건 추출 규모 | 문서 7건 → 청크 256개 → 조건 후보 → 병합 → 검수 | **조건 12개** (해외결제 11 · 계좌개설 1) |
| 검수 통과율 | 병합된 조건 중 트리에 들어간 비율 | **12/16 = 0.75** ([사유 전문](data/review/decisions.yaml)) |
| 조건 추출 정확도 | 수동 라벨 대비 정밀도·재현율 | [eval/results/extraction_accuracy.md](eval/results/extraction_accuracy.md) |
| 근거 표시율 | 판정 중 evidence 링크 비율 | 구조적 100% (스키마 필수 + 인용 검증) |
| 앱에서 해결 불가 비율 | `remedy.actionable_in_app == false` | **해외결제 8/11** |
| 결정론성 | 동일 입력 N회 반복 일치율 | `eval/results/` (팀원 담당) |
| 탐색 시간 대비 | 사람이 직접 확인하는 시간(실측) vs 판정 응답 시간 | [eval/results/lookup_vs_judge.md](eval/results/lookup_vs_judge.md) |

## 데이터 출처와 한계

**실제**: 조건 트리는 KB 공개 안내·약관·FAQ에서 자동 추출한 것입니다. 각 조건에 **출처 URL·원문 인용·수집 일자**가 붙어 있습니다.

> **인용 표기 한 가지.** 표에서 뽑은 조건의 인용은 셀을 `|` 로 이어 붙인 형태입니다
> (예: `1일 한도 | 현금인출/가맹점이용 | 600만원 상당의 달러(USD) 환산액`).
> 각 셀은 원문에 그대로 있지만 `|` 는 **저희 분할기가 넣은 기호**이므로, HTML을 그대로 검색하면
> 이 문자열은 나오지 않습니다. 12개 조건 중 1개가 여기에 해당합니다.
**가상**: 사용자 상태는 데모용 프로필입니다. 실제 연동에는 내부 API가 필요합니다.

> 이 시스템에서 가짜는 **사용자 상태 하나뿐**입니다. 나머지는 전부 실제 문서에서 나옵니다.

전체 한계와 근거 등급은 [docs/기획안.md](docs/기획안.md) 12장 및 [docs/EVIDENCE.md](docs/EVIDENCE.md) 참조.

### 수집 규율
- robots.txt 확인 후 허용 경로만, 요청 간격 1초 이상
- 공시·안내 페이지만 수집 (로그인 뒤 개인화 페이지 제외)
- 원문 재배포 없이 **인용 스니펫 + 출처 URL**만 표시
- 모든 조건에 수집 일자 기록 (약관은 개정됨)

