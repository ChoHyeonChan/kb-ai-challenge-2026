## 0. 이 프로젝트가 뭘 하는 건지 (1분)

은행 앱은 **"왜 안 되는지"** 를 말해주지 않습니다.

```
앱:    "신분증이 인식되지 않습니다. 다시 촬영해 주세요."
실제:  비대면 계좌개설 안심차단이 켜져 있음 → 아무리 찍어도 안 됨. 영업점 가야 함
```

그래서 우리는 **KB 공개문서에서 조건을 자동으로 뽑아** 조건 트리로 만들고,
사용자 상태와 대조해 **무엇에 막혔는지 + 근거 원문 + 다음 행동**을 판정합니다.

**핵심 주장은 하나입니다 — "같은 입력이면 언제나 같은 답이 나온다."**
판정에는 AI를 쓰지 않고 규칙 엔진만 씁니다. **그걸 증명하는 게 팀원 역할입니다.**

## 1. 5분 세팅 — 그대로 복사해서 실행

### 1-1. 받기

```bash
git clone https://github.com/ChoHyeonChan/kb-ai-challenge-2026.git
cd kb-ai-challenge-2026
```

### 1-2. ★ 보안 훅 켜기 (한 번만, 반드시)

```bash
git config core.hooksPath .githooks
```

> 이걸 안 켜면 실수로 API 키를 커밋할 수 있습니다. **키가 한 번 올라가면 지워도 기록에 남습니다.**
> 이 프로젝트에서 보안은 기능·일정보다 우선입니다.

### 1-3. 파이썬 준비

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate
# Mac
source .venv/bin/activate

pip install -r requirements.txt
```

> Python **3.11 이상** 필요합니다. `python --version` 으로 확인하세요.

### 1-4. 잘 됐는지 확인

```bash
python -m src.extract.assemble --dry-run
```

조건 목록이 주르륵 나오면 성공입니다. **API 키 없이도 여기까지는 됩니다.**

### 1-5. 데모 화면 띄우기

```bash
uvicorn src.api.main:app --reload
```

브라우저에서 http://localhost:8000 → 목표와 프로필을 고르고 판정해 보세요.
**이 화면이 우리가 심사위원에게 보여줄 것입니다.** 한 번 만져보고 시작하는 게 좋습니다.

## 3. 할 일 — 딱 3개입니다

### 담당 폴더

```
tests/          ← 마음대로 하세요
docs/REPRODUCE.md
```

**남의 폴더(`src/`, `data/`)를 고쳐야 하면 먼저 현찬에게 알려주세요.** 고치지 말라는 게 아니라, 모르고 겹치면 서로 날립니다.

---

### ① B6 — 결정론성 테스트 `tests/test_determinism.py` ★ 제일 중요

**증명할 것**: 같은 트리 + 같은 프로필로 100번 판정해도 결과가 똑같다.

**주의 — 이거 모르면 멀쩡한데 테스트가 실패합니다.**

| 필드 | 처리 |
|---|---|
| `evaluated_at` | **비교에서 제외** (실행 시각이라 매번 다름) |
| `unmet` / `met` / `unknown` 배열 | **`id` 기준 정렬 후** 비교 (순서만 다른 건 같은 결과) |
| dict 키 순서 | 무시 (`json.dumps(..., sort_keys=True)`) |

**끝나면**: 결과를 `eval/results/determinism.md` 에 **실제 출력 그대로** 붙여넣기.
"될 것이다"가 아니라 "돌려봤더니 이랬다"가 필요합니다.

---

### ② B7 — 엣지 테스트 `tests/test_edge.py`

**증명할 것**: 이상한 입력에도 죽지 않고, **모르면 모른다고 답한다.**

넣어볼 것:
- 프로필이 텅 빈 경우 → `indeterminate` 가 나와야 함 (`ok` 가 나오면 **버그**)
- 값이 `null` 인 경우 → 그 조건은 `unknown` 으로 분류
- 없는 `goal_id` / 없는 `profile_id` → 404, 크래시 아님
- 숫자 자리에 문자열이 온 경우

> **판정이 `ok` 를 남발하면 안 됩니다.** 모르는 상태에서 "됩니다"라고 답하는 게
> 이 프로젝트에서 가장 나쁜 실패입니다. 그걸 못 하게 막는 게 이 테스트입니다.

## 4. Codex에 넣을 말 — 그대로 복사하세요

### 4-1. 맨 처음 한 번 (프로젝트를 이해시키기)

```
이 저장소는 KB AI 챌린지 출품작이야. 먼저 아래 파일을 순서대로 읽고,
읽었으면 "무엇을 만드는 프로젝트인지 3줄로 요약"해줘. 요약이 맞는지 내가 확인할게.

1. AGENTS.md          ← 이 프로젝트의 개발 규약. 절대 규칙이 있음
2. README.md          ← 무엇을 만드는지
3. docs/팀원_시작하기.md  ← 내가 맡은 일
4. src/judge/schema.py  ← 데이터 구조 (C1/C2/C3)
5. src/judge/engine.py  ← 판정 함수

읽기 전에 코드를 쓰지 마.
```

### 4-2. 결정론성 테스트 (B6)

```
tests/test_determinism.py 를 만들어줘.

목적: 판정 엔진이 결정론적이라는 것을 증명한다.
      (같은 입력이면 언제나 같은 출력. 우리 제안서의 핵심 주장이야)

방법:
- data/trees/*.json 과 data/profiles/*.json 의 모든 조합에 대해
- src.judge.engine.judge(tree, profile) 를 100회 호출
- 결과가 전부 같은지 확인

반드시 지킬 것:
- Verdict.evaluated_at 은 실행 시각이라 매번 다르다 → 비교에서 제외할 것
- unmet/met/unknown/low_confidence 리스트는 id 기준으로 정렬한 뒤 비교할 것
- dict 비교는 json.dumps(..., sort_keys=True, ensure_ascii=False) 로 할 것
- pytest 로 실행되게 할 것
- 파일은 200줄 이하, 함수는 40줄 이하 (AGENTS.md 규칙)
- 주석은 한국어로

그리고 실행 결과를 사람이 읽을 수 있게 요약 출력하는 함수도 만들어줘.
(조합 수 / 반복 횟수 / 일치율) — 이 출력을 제출물에 넣을 거야.

만들었으면 실제로 pytest 를 돌려서 통과하는지 보여줘. 안 돌려봤으면 다 됐다고 하지 마.
```

### 4-3. 엣지 테스트 (B7)

```
tests/test_edge.py 를 만들어줘.

목적: 이상한 입력에도 죽지 않고, 모르면 모른다고 답하는지 확인한다.

케이스:
1. 프로필이 완전히 비어 있음 → verdict 가 "indeterminate" 여야 한다.
   ★ "ok" 가 나오면 실패다. 모르는데 된다고 답하면 안 된다.
2. 프로필 값이 null → 그 조건이 unknown 목록에 들어가야 한다
3. 존재하지 않는 goal_id 로 API 호출 → 404 (크래시 아님)
4. 존재하지 않는 profile_id 로 API 호출 → 404
5. 숫자를 기대하는 조건에 문자열이 들어옴 → 크래시 없이 unknown 처리
6. 조건이 0개인 트리 → 크래시 없음

API 테스트는 fastapi.testclient.TestClient 를 써.
pytest 로 실행되게 하고, 주석은 한국어로.
파일 200줄 / 함수 40줄 이하.

만들었으면 실제로 돌려서 결과를 보여줘. 실패하는 케이스가 있으면
테스트를 고치지 말고 나한테 먼저 알려줘 — 진짜 버그일 수 있어.
```

## 6. 확인 없이 "됐다"고 하지 않기

AI가 만든 코드는 **그럴듯한데 안 돌아가는 경우가 많습니다.**

```
✅ pytest 를 실제로 돌렸고, 출력이 이렇습니다  ← 이게 완료
❌ 코드를 작성했습니다 / 될 것 같습니다        ← 이건 완료 아님
```

우리 제출물의 무기는 **"실제로 돌려봤다"** 입니다.
숫자 하나하나가 발표에서 나오므로, 직접 돌린 것만 적어주세요.
