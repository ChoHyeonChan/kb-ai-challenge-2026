## 1. 먼저 — 당신이 맡은 일이 왜 중요한가

역할이 **"검증·증거·문서"** 인데, 이건 잡무가 아니라 **배점의 35점을 직접 담당**한다.

| 배점 | 무엇으로 판정되나 | 담당 |
|---|---|---|
| 기술 적정성 20점 | *"같은 입력에 같은 출력이 나오는가"* → **결정론성 테스트 결과** | **당신** |
| 기술 실현 가능성 15점 | *"제3자가 재현할 수 있는가"* → **클린설치 재현 기록 + 엣지 테스트** | **당신** |

공모전 채점 데이터에서 확인된 것: **끝까지 작동한 제출물은 41.7%뿐**이고, **README와 실물이 다른 것이 최다 탈락 사유**다. 즉 "돌아간다는 걸 증명하는 사람"이 있는 팀이 이긴다.

그리고 기술설명서를 최종적으로 쓰는 사람이 **직접 측정한 사람**이면, 발표에서 숫자를 자기 언어로 말할 수 있다. 그게 심사에서 티가 난다.

## 3. AI(Codex)에게 일 시키는 법

AI를 많이 안 써봤다면 이 절만 읽어도 충분하다.

### 3.1 시작할 때 반드시
```
1. AGENTS.md를 먼저 읽게 한다
   → "AGENTS.md를 읽고 우리 프로젝트 규약을 파악해줘"
2. 지금 작업할 파일/폴더를 지정한다
   → "tests/test_determinism.py를 만들 거야"
3. 완료 기준을 먼저 말한다
   → "동일 입력 10회 실행해서 결과가 완전히 같은지 확인하는 테스트"
```

### 3.2 작게 쪼개서 시킨다
❌ "결정론성 테스트 만들어줘"
✅ "판정 결과 JSON 두 개가 완전히 같은지 비교하는 함수부터 만들어줘. 순서 차이도 잡아야 해."
→ 그다음 "이걸 10회 반복하는 러너를 붙여줘"

**한 번에 큰 걸 시키면 그럴듯하지만 안 돌아가는 코드가 나온다.** 작게 시키고 매번 돌려본다.

### 3.3 AI가 자주 하는 실수 — 이것만 알아도 반은 막는다

| 실수 | 증상 | 대응 |
|---|---|---|
| **없는 함수·옵션을 지어냄** | import 에러, 존재하지 않는 인자 | 실행해보면 바로 드러남. **반드시 돌려본다** |
| **"완료했습니다" 후 안 돌아감** | 테스트 안 하고 보고 | "실제로 실행해서 결과를 보여줘"라고 요구 |
| **파일 통째로 재작성** | 남의 코드까지 바뀜 | "이 함수만 고쳐줘"로 범위 지정 |
| **요청 안 한 것까지 개선** | diff가 예상보다 큼 | 변경된 파일 목록을 항상 확인 |
| **에러를 숨김** | `except: pass` | 이거 보이면 바로 지적 |
| **같은 실패를 반복** | 3번째 같은 에러 | 멈추고 사람에게 상황 정리 요청 |

### 3.4 결과를 믿기 전에
- [ ] **직접 실행했는가** (AI가 말한 게 아니라 내가)
- [ ] 변경된 파일 목록을 봤는가
- [ ] 테스트가 진짜로 뭔가를 검증하는가 (`assert True` 같은 껍데기 아닌지)

> **"AI가 됐다고 했다"는 증거가 아니다.** 터미널 출력이 증거다.

## 4. 우리 프로젝트에서 특히 조심할 것

### 4.1 ★ 판정 로직에 LLM을 넣지 않는다

우리 시스템의 핵심 주장이 **"같은 입력에 같은 출력"** 이다. 그래서 `src/judge/` 안에서는 LLM을 부르지 않는다.

Codex가 "LLM으로 판단하게 하면 유연해집니다" 같은 제안을 하면 **거절한다.** 그게 우리 차별점을 무너뜨린다.

당신의 B6 테스트가 이걸 지키는 마지막 방어선이다. **일치율이 100%가 아니면 어딘가에서 LLM이나 랜덤이 끼어든 것이다.**

### 4.2 계약(C1/C2/C3)을 혼자 바꾸지 않는다

세 사람이 이 세 개로 연결돼 있다. 필드 하나 바꾸면 남의 코드가 깨진다.
바꿔야겠다 싶으면 **먼저 말한다.** 정의는 `src/judge/schema.py`가 단일 출처.

### 4.3 프로필(C2)에 "모르는 값"은 `null`로

추측해서 채우지 않는다. `null`이면 판정에서 `unknown`으로 분류되고, 그게 우리 설계 철학이다.
**전부 ✓/✕로 채운 화면은 정직하지 않다.**

## 6.5 API 키 — 당신은 가질 일이 없다

우리 설계상 **LLM 호출은 `src/extract/`와 `src/resolve/`에만** 있고 그건 현찬 담당이다.
당신이 맡은 `src/judge/`(판정 엔진)와 `tests/`는 **LLM을 쓰지 않는다.**

> **키를 주고받을 일이 아예 없다.** 키 공유가 유출 경로 1순위인데 그게 원천 차단된다.

혹시라도 키를 다루게 되면:
- 코드에 문자열로 박지 않는다 → `os.getenv()`
- `.env`는 **절대 커밋하지 않는다** (`.gitignore`에 이미 등록됨)
- 커밋 전 `git status`로 확인
- **실수로 커밋했다면 파일을 지워도 소용없다.** 히스토리에 남으므로 **즉시 현찬에게 알리고 키를 폐기·재발급**해야 한다
