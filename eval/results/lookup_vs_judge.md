# 수동 확인 vs 시스템 판정 (대비)

> 활용 가능성의 정량 근거. **추정치가 아니라 실측이다.**
> 다만 이 비교에는 전제가 있으므로 아래 "이 비교의 한계"를 함께 읽어야 한다.

## 측정값

| | 사람이 직접 확인 | 시스템 판정 |
|---|---|---|
| 대상 | 해외 온라인 결제 조건 7개 | 동일 |
| 소요 | **326.37초** (5분 26초) | **0.039 ms** (중앙값, 200회) |
| 검색 필요 | **4 / 7** | 0 |
| 앱을 벗어남 | **2 / 7** | 0 |
| 결론에 도달하지 못한 조건 | **1건** (T&E 한도 → "고객센터 문의" 안내) | 0 |
| 인증 장벽으로 확인 실패 | **2건** (1차 측정자, 카드 비밀번호 미기억) | — |
| 판정마다 근거 원문 | 없음 (사용자가 기억해야 함) | **100%** (출처·인용·수집일) |

- 사람 측정: `manual_lookup_time.md` (측정자 2명, Galaxy S24+ / iPhone 13)
- 시스템 측정: 조건 7개 트리 × 프로필 1종, 200회 반복, 중앙값

## ★ 이 비교의 한계 (반드시 함께 제시할 것)

**속도 배수를 강조하지 않는다.** 두 값은 같은 일을 재고 있지 않다.

```
사람이 한 일:   조건을 찾고  +  자기 상태를 확인하고  +  대조한다
시스템이 한 일: 조건을 이미 갖고 있고, 상태를 입력받아  +  대조한다
```

- 시스템은 **사용자 상태를 이미 안다고 전제**한다. 실제 서비스에서는 내부 API 조회 시간이 추가된다.
- 따라서 0.039ms 는 **판정 로직의 비용**이지 서비스 응답 시간이 아니다.
- 배수(수백만 배)를 내세우면 이 전제를 숨기는 것이 되므로 **쓰지 않는다.**

## 그래서 이 측정이 말하는 것

**시스템이 없애는 것은 "조회 시간"이 아니라 "찾고 대조하는 부담"이다.**

1. **탐색 부담의 이전** — 사용자가 4번 검색하고 2번 앱을 벗어나야 했던 일을, 시스템은 한 번의 판정으로 대체한다.
2. **결론 보장** — 사람은 7개 중 1개에서 결론에 도달하지 못했다(고객센터 문의 안내). 시스템은 알 수 없으면 `unknown` 으로 **명시**한다. 모르는 채로 방치하지 않는다.
3. **근거의 동반** — 사람이 확인한 결과에는 근거가 남지 않는다. 시스템 판정에는 출처·원문·수집일이 붙는다.

## 재현

```bash
python - <<'PY'
import time, statistics
from src.judge.engine import judge, load_tree, load_profile
tree = load_tree('data/trees/overseas_payment_online.json')
prof = load_profile('data/profiles/overseas_blocked.json')
judge(tree, prof)
ts = []
for _ in range(200):
    t0 = time.perf_counter(); judge(tree, prof); ts.append((time.perf_counter()-t0)*1000)
print(f"median {statistics.median(ts):.3f} ms / max {max(ts):.3f} ms")
PY
```
